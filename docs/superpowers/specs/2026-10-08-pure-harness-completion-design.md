# Pure Harness 완성 설계 — 사용자 검토안 (2026-10-08)

## 목적과 완료의 뜻

처음 쓰는 사람이 Harness 설치 안의 고정된 `project/`에서 새 제품 프로젝트를 시작하거나 기존 프로젝트를 비파괴 연결하고, 실제 AI 도구에서 역할·Skill·훅 및 대시보드가 작동하는지 확인할 수 있게 한다. 이미 완성된 것처럼 보이는 후보 생성이나 화면만으로 완료를 선언하지 않는다. 이 문서는 **변경된 단일 프로젝트 설계의 검토안**이며 아직 구현 계획이나 설치 승인, 원본 프로젝트 정리 승인이 아니다. 실제 관찰과 통과/미확인 기준은 [완료 확인표](../../pure-harness-completion-checklist.md)에 둔다.

사용자의 최신 결정은 **Harness 하나 = 제품 프로젝트 하나**다. 사용자가 안팎 배치를 모두 허용했으므로, 이 설계는 사용·설치가 단순한 고정 내부 `project/`를 선택한다. 제품의 실제 소스와 독립된 Git 정체성은 그 child에 있으며, 엔진 구현은 Harness 루트에 남는다. 외부 경로 선택 모드·레지스트리·프로젝트 전환·두 번째 프로젝트 접근은 없다. 제품 정책·문구·경로를 범용 엔진 소스에 하드코딩하지 않는다.

```text
pure-harness/                 # Harness 코어 Git 저장소
  project/                    # 단 하나의 실제 제품 소스, 자체 Git 저장소/remote/history
  .harness/                   # 이 설치만의 설정·tasks·memory·runtime (로컬 전용)
  harness/  preview/  scripts/ # 범용 엔진 구현
```

Harness 루트 Git의 ignore 규칙은 `project/**`와 `.harness/**`를 제외해야 한다. 코어 Git의 add/status/commit/push가 제품 소스나 로컬 상태를 다루지 않아야 하며, 제품 Git 작업은 `project/`의 자체 저장소에서만 한다. `project/.git`이 없으면 부모 Harness Git을 제품 저장소로 오인하지 않고 중단한다. 검증된 worktree는 **동일 제품 Git 정체성**에 속할 때만 허용하며 두 번째 관리 프로젝트가 아니다. 코어 유지보수 runtime 역시 두 번째 사용자 프로젝트로 취급하지 않는다.

## 현재 기준과 결손

구현 기준 커밋은 `05c1ba4`다. 명시적 프로젝트 컨텍스트 검증, 선택 runtime, 대시보드, 수동 Codex rollout 가져오기와 프라이버시 제한, 네 대상 후보 내보내기와 **일회용 checkout 시험 설치**는 있다. 그러나 이 구현은 외부 checkout·project ID·binding의 3개 입력을 전제로 한다. 고정된 `project/` 소스 배치는 **아직 없다**. 이는 새/기존 프로젝트의 안전한 연결이나 네이티브 동작 검증과 다르다. AI 설정·훅은 자동 연결되지 않는다. `checkCutover`는 호출자가 제시한 수치·목록을 신뢰하지 않으므로 항상 `ok: false`다. 이를 임의의 `true`나 가짜 0건으로 바꾸지 않는다.

네 대상의 `nativeSmoke`는 모두 `unverified`다. 로컬 설치 Codex 0.161.0에 대한 이전 역할 프로브는 실제 spawn 호출이 0회였고 모델 응답이 `agent_type` 부재를 주장한 것뿐이다. 따라서 사용자 정의 역할 실행 가능 여부는 **미검증**이지 Codex 전체에서 불가능하다고 판정한 사실이 아니다. API/CLI의 실제 스키마·도구 응답과 새 세션 관찰만 증거로 채택한다. Claude Code 실제 시험과 OpenCode·Antigravity 완료는 이번 야간 필수 범위에서 제외하고 미인증 상태로 남긴다.

화면 복원 `f3424b7`과 읽기 쉬운 가이드 `60c8c2e`는 준비된 별도 브랜치 작업이며 이 기준 브랜치에 아직 합쳐지지 않았다. 로케일 컴포넌트 수정 `551168e`는 독립 검토와 63/63 테스트를 통과했지만 통합 전이다. 화면의 일부 오류 문구 로케일은 1단계 후속 작업이다. 합친 후 실제 위젯/모듈을 연결한 DOM 검증과 전체 관련 테스트를 한 번 수행해야 한다.

## 접근 선택

1. **선택: 단일 설치의 고정 `project/` + 얇은 네이티브 브리지.** 기존 범용 엔진을 활용하되 제품 코드는 자체 Git 저장소, 로컬 상태는 `.harness/`, 도구 발견에 필요한 소유 파일만 `project/`에 둔다. 경로를 추측하거나 여러 프로젝트 중 고르지 않는다.
2. 외부 checkout 선택/레지스트리 유지: 사용자에게 불필요한 경로 입력·전환·두 번째 프로젝트 가능성을 남겨 이번 단일 프로젝트 UX에 맞지 않으므로 제외한다. 기존 검증·runtime 기능은 새 경계에 맞춰 보존한다.
3. 엔진 전체를 `project/`에 복사하거나 runtime 격리만 하고 도구 연결은 수동 유지: 각각 제품 Git 오염 또는 실제 첫 작업 연결 결손이 생겨 제외한다.

## 사용자가 보는 흐름

`npm run setup`을 새 대화형 진입점으로 제안한다. **현재 존재하는 명령이 아니다.** `새 프로젝트`/`기존 프로젝트 연결`과 사용할 AI 도구를 묻고, 기존 프로젝트일 때만 가져올 원본 경로/remote를 받는다. 대상은 언제나 이 설치의 `project/`다. 기본 안내는 Codex 하나로 시작하되 도구 선택권을 보존한다. 변경 목록·소유 파일·충돌·백업·검증 가능/불가능 항목을 읽기 전용 계획으로 보여주고, 명시적인 Apply에서만 쓴다. `npm run preview:live`와 `status`도 자신의 설치와 고정 child에서 컨텍스트를 유도한다. 사용자에게 project ID/checkout/binding 세 플래그나 프로젝트 선택 화면을 요구하지 않는다. 비대화형 경로에도 같은 계획·승인 게이트가 필요하다.

새 프로젝트는 비어 있고 검증된 `project/`에만 제품용 child Git을 안전하게 만든다. 기존 프로젝트는 원본을 이동·삭제하지 않고 검토 후에만 `project/`로 복사/clone한다. 기존 원본의 커밋·remote·history는 child Git에 보존하며, 원본의 미추적·무시 파일 처리와 목적지 충돌은 계획에 드러내고 임의로 버리지 않는다. 사용자 `AGENTS.md`, 사적 설정, `.ai/` 데이터, 기존 도구 설정을 덮어쓰거나 Harness 코어 전체를 복사하지 않는다. 새 고정 child는 의도된 중첩이므로 일반적인 중첩 루트 금지를 해제하는 대신 **정확히 그 canonical 경계만 허용**하도록 validator를 교체한다. `project/` 밖 경로, symlink/reparse 이탈, 두 번째 제품 소스, 불명 Git 정체성, 권한 부족은 쓰기 전에 차단한다.

기존 프로젝트의 `.ai/`, `.codex/`, `.agents/`는 통째로 제품 전용이거나 통째로 범용이라고 가정하지 않는다. 연결 전 파일과 **내용**을 조사해 `범용 역할/Skill/절차/정책`, `제품 전용`, `runtime·사적 데이터`, `혼합`으로 분류하고 경로·해시·소유권·판단 이유를 inventory에 남긴다. 범용 부분은 검토 후에만 Harness의 canonical 소스로 추출하고, 제품 전용은 제품에 남기며, 혼합 문서는 분리안을 검토한다. 특히 제품 이름·문구·ACL·경로·정책을 중립 엔진에 가져오지 않는다. 이 감사는 기존 아티팩트를 실행 의존성으로 삼거나 원본을 수정·정리할 권한이 아니다. 원본 cleanup은 별도 승인을 받는다.

AI 작업 세션은 `project/`에서 시작한다. 부모 Harness의 `AGENTS.md`가 상속될 수 있으므로, 브리지는 코어 유지보수 지침과 제품 프로젝트 지침의 적용 범위를 명시하고 제품 작업에 코어 파일 쓰기나 코어 claim을 요구하지 않아야 한다. 도구 선택 뒤 후보 파일의 실제 네이티브 등록과 Skill 발견 위치를 확인한다. 필요하면 `project/`에 도구 네이티브 형식의 **버전·소유권이 기록된 생성 설정/역할/Skill 파일**을 둔다. 이는 엔진 구현·runtime 복제가 아니며, 상대 경로나 부모 폴더의 자동 발견을 추정하지 않는다. 정적 생성 파일을 이용한 에이전트 사용은 Node 없이도 가능해야 한다. 실시간 훅 기록과 대시보드는 Node가 있는 경우의 선택 기능이다. 네 대상용 결정론적 생성 코드는 유지하되 이번 완료에서 실사용 증거의 필수 대상은 로컬 Codex다. 다른 세 대상은 후보/문서 상태만 정확히 표시하며 지원 완료로 홍보하지 않는다. 모델, 동시성, fork, 토큰 최적화, 글로벌 도구 설정, provider/auth를 설치 과정에서 변경하지 않는다. 선택 도구/버전에서 필요한 역할 호출이나 권한 경계가 확인되지 않으면 기능별 `미확인`을 표시하고 조용히 기본 역할로 대체하지 않는다.

**독립 실행 경계:** Pure Harness 코어는 기존 제품에 Harness 파일·스크립트·`.codex/`·`.agents/`·`.ai/`가 전혀 없고 그 제품이 접근 불가해도 동작해야 한다. 필수 역할·Skill·설정 생성기·runtime·UI는 Harness 자신의 canonical 소스에서 제공한다. `setup`은 그것만으로 빈 중립 child에 최소 발견 파일을 부트스트랩한다. 기존 프로젝트 아티팩트는 선택적인 감사 입력이지 import·실행의 전제 조건이 아니다. 수동 rollout 원본이 없다면 telemetry는 정직하게 `missing`이며 본문이나 가짜 숫자를 만들지 않는다.

## 안전한 적용·운영·업데이트

Apply는 계획의 대상 경로와 현재 해시를 재검증하고, 소유 파일을 백업·기록한 다음 원자적으로 쓰며 중간 실패 시 소유 범위만 복구한다. 외부 프로세스가 같은 파일을 바꾸면 자동 병합하지 않고 재검토를 요구한다. 설정 병합은 기존 키·주석·훅 순서/의미를 보존해야 한다. `.harness/`의 로컬 설정/pointer 변경은 이전 바이트를 보관하고 원자적 교체와 검증된 롤백을 제공한다. 시스템별 경로와 로컬 상태는 코어 Git에 추적하지 않는다. `update`도 같은 계획→검토→적용→검증 경로를 사용하며 원본 프로젝트 cleanup은 **범위 밖**이다. 기존 `.codex/`나 `.agents/`를 전부 지울 수 있다고 전제하지 않는다. 새 설치는 과거 runtime 이관이 아니다. 기존 외부 binding·runtime은 우선 읽기 전용으로 보존하며, 새 배치로의 전환은 자동으로 추측하거나 실행하지 않는다.

기존 runtime 전환은 별도 경계다. 먼저 기존 파일명·크기·해시, pointer 바이트, 실제 세션/작성자/claim 상태를 읽고 보존한다. 새 선택 프로젝트에서 명령·대시보드·역할·Skill·현재 계약의 다섯 훅을 해당 버전의 실제 지원 범위에서 검증한다. 신뢰 리더는 브리지가 직접 시작·관찰한 세션과 writer/claim의 정지 상태만 증명할 수 있으며, 외부 세션이나 생존 여부를 OS 전역에서 맹목적으로 인증할 수 없다. 관찰 범위 밖 세션이 있거나 상태를 알 수 없으면 legacy cutover는 차단한다. 호출자 입력 배열·숫자·문구는 증거가 아니다. 실패나 사후 검증 실패 시 새 세션을 멈추고 pointer 바이트를 되돌리며 두 runtime을 모두 보존한다. 실제 원본 전환·데이터 이관은 별도 리뷰/승인이 필요하다.

Lifecycle에는 실제 네이티브 인스턴스 ID를 시작·정지·재개·종료에 일치시킨다. 후속 턴은 같은 ID와 고유 turn token으로 조정하고, 훅과 orchestration 기록이 충돌하면 훅의 정확한 이벤트를 우선한다. 응답 없음이나 경과 시간만으로 생존, 성공, 종료를 추론하지 않는다. 런타임 실패는 사용자 작업을 취소하지 않되 화면에 기록 품질을 드러낸다. 토큰 화면은 선택 프로젝트의 실제 rollout만 명시적으로 가져오며, 소스가 없거나 일부만 관찰되거나 태스크 귀속이 불확실하면 `0` 대신 미확인/부분/귀속 불가를 표시한다. 프롬프트, 출력 본문, 자격 증명, 원본 로그 경로를 분석 저장소나 UI에 노출하지 않는다. 작업 선택 유지·새로고침 실패·오래된 표시 상태도 확인한다.

## 검증·통합 경계

구현은 격리된 **Harness 루트 + 고정 `project/` child Git** fixture에서 새 경로와 기존 경로의 읽기 전용 계획, 안전한 Apply, 충돌·중단·재시도·롤백을 먼저 검증한다. 읽기 전용 계획은 바이트 변경이 없어야 한다. 코어 Git ignore/status/commit 경계와 child Git의 remote/history 보존, child `.git` 부재 시 부모 fallback 거부, symlink/reparse 이탈 및 두 번째 프로젝트 거부를 확인한다. 기존 외부 root를 허용했던 validator의 일반 중첩 금지 경로를 새 고정 child 전용 검사로 교체했는지도 회귀 검증한다. 실제 지원되는 Codex 훅과 역할 호출은 설치 버전·모델·세션·권한·명령/도구 응답을 기록한 새 fixture 세션에서 관찰한다. `agent_type` 가능 여부도 실제 지원 스키마와 호출 결과로 판단한다. 기능별 관찰 실패는 원인을 표시하고 해당 항목을 미완료로 남긴다. 전환 게이트에는 가짜 입력이 통과하지 않는 회귀 테스트와 신뢰 리더 증거의 긍정/부정 fixture 테스트가 필요하다.

필수 **cold-start fixture**는 깨끗한 Harness 코어 clone과 별도 Git 정체성을 가진 빈 중립 `project/`만 쓴다. 구형 제품·경로에 접근할 수 없고 child에는 시작 시 `.ai/`·`.codex/`·`.agents/`·Harness 스크립트가 없어야 한다. 이 상태에서 plan의 무변경, Apply의 자체 canonical 소스 기반 Codex 브리지, 작업/runtime, `status`·대시보드, telemetry `missing`/안전한 수동 입력, Node 없는 정적 역할/Skill 소비를 각각 관찰한다. 코어의 정적 repo/import/path 순수성 검사와 런타임 독립성 검사를 둘 다 통과해야 한다. 별도 fixture에서는 무관한 기존 `.codex/` 등과 혼합 파일의 inventory·비파괴 보존을 확인한다. 파일 존재만으로 네이티브 발견이나 독립성을 통과 처리하지 않는다.

UI 브랜치와 가이드 브랜치를 합칠 때 다른 위젯을 가짜 마크업으로 대체하지 않는다. 실제 모듈을 연결한 DOM 테스트에서 탭 전환·내비게이션·토큰 새로고침 실패·차단된 private URL을 확인하고, 관련 전체 suite를 한 번 돌린다. Node가 선택적인 오프라인 갤러리도 열리는 경로로 확인한다. 실제 앱 링크는 실행·검증된 서버의 주소일 때만 보여준다. 안내문은 현재 가능한 수동 흐름과 미래 자동 진입점을 혼동하지 않으며, 구현 후에는 정확한 새/기존 시작 단계와 실패·복구 단계를 제시한다.

사용자가 요청한 밤샘 범위는 위 **완료 기준을 재계획하고 승인 뒤 순서대로 검증하는 것**이지 미확인 기능을 통과 처리하는 것이 아니다. YouTube/문서 내보내기/코드 분석/참고자료/오픈소스/태스크 iframe Skill 아이디어는 이후 별도 판단으로 미룬다. 외부 설치·글로벌 설정·인증·모델 선택 변경은 이번 범위에 없다. 검증 불가한 외부 기능은 명시적으로 미완료로 보고한다.

## 사용자 검토 선택 (최대 세 항목)

1. 소스 배치: 안팎 모두 가능한 선택지 중 사용이 간단한 고정 내부 `project/` child Git 소스와 별도 `.harness/` 로컬 상태를 확정할지.
2. 실사용 완료선: 이번에는 로컬 Codex 네이티브 역할·Skill·훅 증거까지 필수로 하고 다른 세 대상은 `unverified`로 남길지.
3. 원본 정리: 기존 프로젝트 cleanup과 실제 legacy runtime 이관을 이번 완료에서 제외할지.

이 설계는 최신 단일 프로젝트 요구와 내부 배치 선택을 반영한 재검토안이다. 이 문서 자체가 구현 승인이나 진짜 cutover 승인은 아니다. 검토·승인 뒤 구현 계획을 작성한다.
